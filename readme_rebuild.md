# 无线外设电量工具：项目说明与新设备适配

这是一个运行在 Ubuntu 桌面的无线外设电量小工具。它从系统公开电量或已验证的设备协议取得读数，在卡片面板和托盘中显示，并提供接口诊断、原始报告查看与离线标定入口。

如果要把这套能力迁到另一台电脑，或适配另一款 2.4G 键盘、鼠标、耳机，请先阅读本文件，再复制 [prompt_rebuild.md](prompt_rebuild.md) 给具备本机开发与终端能力的助手。那份提示词支持“已有项目上新增适配”和“没有项目时实现基础版本”两种路径。

## 1. 它解决什么问题

2.4G 接收器常能作为键盘或鼠标正常使用，但系统没有显示外设电量。原因可能是驱动没有公开电量、设备只使用私有查询协议，也可能是接收器根本没有提供可读取的电量接口。

本项目将“取得可信读数”与“显示和刷新读数”分开：先证明数据属于目标设备，再把它接入统一服务。不能仅修改 VID/PID，就让任意接收器具备电量读取能力。

这里的“2.4G”指通过 USB 接收器连接的无线外设，不是 Wi-Fi 网络设备。接收器被枚举出来，也不代表无线外设当前已连接或已开机。

## 2. 已实现功能与支持范围

| 能力 | 当前实现 |
|---|---|
| 单次读取 | CLI 输出百分比、来源、状态和时间；成功退出码 0，其余为 2 |
| 卡片面板 | 按显式绑定生成卡片，显示百分比、进度、来源和更新时间 |
| 数字托盘 | 显示第一台绑定设备；刷新、打开面板、退出和悬停提示 |
| 过期显示 | 有历史值时保留灰色数字并注明过期；无可靠读数才显示问号 |
| 刷新与退出 | 默认 60 秒、可调 30～1800 秒；事件驱动、有界工作池、取消与完整收尾 |
| 多设备 | 已有双模拟设备测试；不等于已认证多种真实外设 |
| 调试 | HID 枚举、受限厂商监听、已声明 Feature 读取、显式试发、离线标定 |
| 安装 | Ubuntu 用户级桌面链接、自启设置，以及经审阅的定向权限规则 |
| 固定排序 | 可选 GNOME 46 用户扩展，只固定本工具位置；依赖宿主和实际登录验证 |

真实协议目前仅验证过本机 **AULA F98Pro 的特定 2.4G 接收器配置**：`05AC:024F`、产品 `2.4G Dongle`、USB `bcdDevice=0121`、接口 `03` 和精确描述符。这个事实不适用于所有 F98Pro 版本，也不适用于其他品牌。USB 版本不能当作已经识别的固件版本。

标准 HID 的 Battery Strength 字段可以发现，显式 Feature 报告可以做候选解码；目前没有已启用的通用标准 HID 自动读取后端。JSON 标定也不会自动安装后台协议插件。

当前运行实现以 Ubuntu/Linux 为基础：Python 标准库、`ctypes`、系统 Tk、GIO/GLib 和 SNI 托盘宿主，无第三方 Python 包。其他 Linux 桌面须核对系统接口与托盘支持；Windows/macOS 需要重做平台层，不能直接运行这些 Linux HID 和桌面实现。

## 3. 陌生电脑上的起步方式

先确认项目路径、Python 解释器、操作系统、桌面会话和目标外设，再决定读什么、装什么。缺少 Tk 不妨碍先做 CLI 和协议调查；没有托盘宿主时先交付可用面板，不强行重启桌面。

已有本项目时，可以先运行以下不发送 HID 查询的入口：

```bash
python3 -B my_devices.py --help
python3 -B my_devices.py --list-devices --json
```

下面是**模板命令**，必须把 `VVVV`、`PPPP` 替换为该电脑实际枚举出的 VID/PID；不要直接使用本项目默认的 F98Pro 标识：

```text
python3 -B my_devices.py --diagnose --vid VVVV --pid PPPP
python3 -B my_devices.py --onboard --vid VVVV --pid PPPP
```

同 ID 多个接收器时，额外使用枚举结果中的 `--usb-path`。`hidrawN` 会随插拔改变，不是长期身份。先区分“沙箱看不到节点”“普通用户无权限”“没有匹配协议”，不要用管理员启动 GUI 来掩盖问题。

只有在目标和查询协议已经确认后，才使用主动读取、面板或托盘；这些入口可能向设备发送电量查询。不要在陌生设备上试跑 `--probe-aula` 来碰运气。

## 4. 架构：新增设备改哪里

```text
CLI / Panel / 调试操作
        ↓
ApplicationService：发现、状态、刷新与退出
        ↓
系统电量来源 → 静态适配器注册表 → 已验证设备协议
        ↓
接收器事务 / 有界读写 / 取消与资源清理
        ↓
统一快照 → 主线程卡片与原生托盘
```

| 文件或目录 | 新设备接入时的职责 |
|---|---|
| `keyboard_power/domain/matching.py` | 精确身份与匹配/拒绝结果，不做设备 I/O |
| `keyboard_power/adapters/profiles.py` | 设备档案、型号显示名、接口、描述符和已支持版本 |
| `keyboard_power/adapters/新设备模块.py` | 新协议适配器；请求构造、回复解析和错误转换 |
| `keyboard_power/adapters/base.py` | `ReadContext`、`BackendResult` 与适配器契约 |
| `keyboard_power/application/registry.py` | 只注册已审阅的适配器，冲突时拒绝自动发送 |
| `keyboard_power/application/reader.py` | 系统新鲜值优先；过期值允许已支持来源后备查询 |
| `keyboard_power/application/service.py` / `scheduler.py` | 状态、连接代次、刷新合并、有界并发和取消 |
| `keyboard_power/transport.py` | Linux Output 封装、物理接收器级事务锁 |
| `keyboard_power/platform/installation.py` | 新设备确有需要时增加独立访问策略 |
| `tests/` | 真实字节夹具、身份负例、失败状态与生命周期测试 |

适配器公开契约如下；协议握手仍归各自模块，不把不同设备强行塞入同一个交换循环：

```text
profile -> DeviceProfile
match(interfaces) -> MatchResult
read(interfaces, ReadContext(cancel_fd, trace, clock)) -> BackendResult
BackendResult.to_legacy() -> 现有 CLI / IPC 字段
```

外部字段为 `device/percent/source/updated_at/checked_at/status/reason`。`percent=None` 表示未知，失败不变成 0；通用模型允许有效 0，但具体协议可以因证据不足而拒绝某种 0 值。`updated_at` 是样本时间，可以未知；`checked_at` 是检查时间，二者不能混用。

新设备通常不需要给卡片和调度增加品牌分支。但默认 VID/PID、用户绑定、权限策略、调试预设和验收脚本中的旧设备断言仍要审查，不能只增加一个 parser 就宣布全部适配完成。

## 5. 从未知设备到支持设备

### 第一步：定位唯一目标

收集品牌/完整型号、连接模式和接收器归属；记录 VID/PID、产品字符串、USB 版本、接口号、物理路径、顶层集合、Report ID、报告长度，以及描述符原文与 SHA256。

同 VID/PID、相似外壳或相似描述符只能形成候选。先分清一台接收器的多个接口和多台相同接收器，避免把普通按键通道当厂商控制通道。

### 第二步：优先找系统公开值

检查与目标确实关联的内核电量、UPower 或平台公开接口。不能拿笔记本主机电池、另一个蓝牙设备或无效缓存顶替目标电量。离散等级不冒充精确百分比，未知采样时间不伪造。

### 第三步：确认标准报告或私有协议

存在标准字段时核对报告类型、编号、位偏移、逻辑范围和实际含义。不存在标准字段不等于没有私有协议，也不等于可以扫描未知命令。

私有协议优先采用型号与版本明确的官方资料、可信原始源码或针对该设备的授权抓包。必须知道命令是读电量，而不是灯效设置、初始化、复位或固件操作。没有依据就停在诊断与候选解析，不生成“看起来合理”的电量。

### 第四步：先做离线解析，再做有限实测

用纯函数实现请求和回复解析，写出长度、Report ID、前缀/命令、序号、分片、校验范围与端序、无效值和百分比换算规则。拒绝不相关报告和错误样本。

Linux 未编号 Output 的写缓冲区通常需要前置 `00`；未编号 Input 不因此多出一个字节。Feature ioctl 又有自己的缓冲区约定。按已确认平台与报告类型封装，不能照抄 F98Pro 的 32 字节长度或偏移。

随后在唯一匹配、具备相应授权的接口上做一次有超时、可取消的查询，与设备屏幕或官方值独立对照。尽量取得不同电量/状态样本；只有一次对照时明确标为单点验证，充电、低电量、休眠、关闭、断连等缺失场景继续列为未验证。

### 第五步：接入与最小权限

添加严格 profile 和独立适配器，复用完整事务、打开后身份复核、超时和取消，不自行枚举或访问 Tk。经证据审阅与实测后才加入 `REVIEWED_ADAPTERS`，未知版本和歧义不自动发送。

确需直接 HID 访问时，为目标接口增加独立审阅的 `AccessPolicy` 和窄规则。不要直接复制本机 F98Pro 安装器给其他设备，不放开所有 hidraw、不解绑正常键鼠驱动、不以 root 常驻运行。

### 第六步：绑定、展示与安装

协议支持完成后，参考 [设备绑定示例](packaging/devices.example.json) 创建该电脑实际设备的配置，修改名称、VID/PID 和必要的物理端口。绑定只选择设备，不定义协议。离线校验后再运行：

```bash
python3 -B my_devices.py --check-config /path/to/devices.json
python3 -B my_devices.py --once-all --targets /path/to/devices.json
python3 -B my_devices.py --panel --targets /path/to/devices.json
```

`/path/to/devices.json` 必须替换为新文件实际路径。单次使用不保存；确认后可显式执行 `--set-targets`，供下次面板/自启使用。原 `--once --vid ... --pid ...` 保持单设备输出，多设备使用单独的 `--once-all`。

最后才处理桌面链接、无终端启动、自启和托盘。读取设置不能替用户启用自启；不同桌面不照搬 GNOME 扩展。左右键行为和固定顺序属于托盘宿主能力，必须在目标电脑验证。

## 6. 基础功能的验收清单

| 项目 | 必须取得的结果 |
|---|---|
| 身份 | 错产品/版本/描述符、重复候选不会误发；插拔后重新发现节点 |
| 数据 | 正确样本通过，错误长度/编号/校验/范围被拒绝；与独立值对照 |
| 状态 | 无数据为未知，有历史值的失败为过期，恢复后使用新读数 |
| 面板 | 百分比、进度、来源与时间正确；后台不直接操作 Tk |
| 托盘 | 有宿主时显示数字/过期状态，菜单可用；无宿主时保留可操作面板 |
| 生命周期 | 单实例；连续三次启停、读取中退出，无残留线程/fd/子进程/图标 |
| 性能 | 事件驱动、无空闲 sleep/高频轮询；按目标机实测 CPU，记录时长与统计范围 |
| 权限与安装 | 普通用户运行，规则最窄；入口确为链接；自启可由用户启停且不被自动修复 |

本项目可以先运行 `python3 -B -m unittest discover -s tests -q` 做隔离回归。真实桌面脚本可能退出已有实例、查询设备或截图；先读 [维护说明](docs/maintenance.md)，并为新设备更新原脚本中的 F98Pro 固定断言后再用。旧电脑的通过记录和模拟设备测试不是新设备的验收证据。

## 7. 哪些能自动化，哪些需要人

能自动化：环境与能力收集、严格匹配既有档案、离线解析和负例、配置校验、已支持来源刷新、模拟设备生命周期测试、审阅后的安装计划生成。

需要独立证据或人工动作：外设真实型号与接收器归属、未知命令含义、屏幕/官方电量对照、物理插拔、真实登录、充电全周期。设备若未暴露电量接口，可靠软件方案可能不可行；此时交付明确的不支持原因和已完成基础框架，不伪造成功。

每阶段按“备份与校验 → 本阶段实现 → 隔离自测 → 授权实测 → 记录证据 → 下一阶段”推进。备份恢复到新目录比较，不覆盖后续用户修改。平时不写应用日志；用户主动保存的配置、证据、备份与截图是不同用途，分享前检查脱敏。
