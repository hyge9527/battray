# 带阶段备份的持续重构提示词

请重构 `{项目路径}`，方案为 `{已审阅的实施文档}`，保留 `{入口、协议、输出及用户设置契约}`。
当前阶段：`{阶段编号与完成证据}`。已授权验证：`{模拟范围、真实设备命令、是否可启停现有实例}`。

按“备份 → 本阶段重构 → 自测 → 保存阶段补丁与结果 → 下一阶段备份”连续推进，直到实施完成或遇到需要外部动作的卡点。

1. 先读取项目指令、已有修改与相关技能。无有效 Git 仓库时不初始化、不重置；用完整文件清单、归档及 SHA256 建立本轮基线。
2. 备份排除递归备份、环境挂载和可重建缓存，逐文件核对归档内容；明确未包含的项目外配置。给出恢复到新目录、逐项比较的方法，不覆盖后续用户修改。
3. 每阶段只交付有真实消费者的边界。区分结构迁移与有意修复，不为了目录草图创建空转发层。
4. 保留协议字节、资源所有权和原测试断言；必要时机械迁移 mock/断言位置，不能为了绿测试放宽安全条件。锁、代次、取消、退出用模拟设备和假时钟验证。
5. 当前阶段未通过不得继续叠加下一阶段；定位并修复本阶段问题，不回退他人修改。通过后保存可应用的独立补丁、校验与验证范围，再备份进入下一阶段。
6. 实机验收只能使用已授权且已验证的命令；事先说明是否启停现有程序、截图或改变设置。模拟成功不冒充硬件认证，历史 CPU 成绩不冒充本轮实测。
7. 不能代做物理插拔、设备屏幕确认或真实登录。遇到这些卡点，说明已完成部分、缺少的证据和最小人工步骤；等待期间完成不依赖它们的文档与审查。

交付当前架构、使用/适配引导、各阶段备份位置、实际测试结果，以及已确认风险与验证空白；不要只罗列改动文件或宣称已支持未实测的设备。
