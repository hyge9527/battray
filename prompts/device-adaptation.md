# 新设备适配提示词模板

复制下文，替换花括号字段。未提供的信息填“未知”，不要填猜测值。

---

请在现有 Ubuntu 外设电量工具中适配 `{品牌与完整型号}`，不是重新开发一套独立应用。

输入：

- 项目：`{绝对路径}`；目标平台/会话：`{Ubuntu 版本、GNOME/X11/Wayland 等已知信息}`。
- 连接方式：`{2.4G / 蓝牙 / 有线}`；设备与接收器归属证据：`{照片或核对结果}`。
- VID/PID、产品字符串、USB 版本、接口及描述符：`{现有枚举，缺失则只读收集}`。
- 可参考协议：`{原始来源与版本}`；真实样本/屏幕对照：`{资料或未知}`。
- 当前会话已授权的操作：`{只读诊断 / 明确的查询报文 / 安装 / 真实验收}`。

请先读取项目指令、README 和 docs/device-adaptation.md，保护现有修改和已适配设备。无有效 Git 基线时先保存受影响文件快照，不初始化仓库或提交。

约束：标准库 + ctypes，GUI 沿用 tkinter，无第三方 Python 包；允许已有系统共享库。不开日志、不自动扩大权限，不抢占普通按键，不发送配置/复位/固件命令，不将未知电量写成 0%。

按阶段推进：

1. 只读定位唯一目标，区分沙箱不可见、权限不足、歧义和未连接；检查内核/UPower 电量归属和 HID 描述符。
2. 标明哪些能力已存在、哪些只是候选。没有标准电量不等于没有私有电量；相同 VID/PID 或相似描述符不等于型号兼容。
3. 先以来源和真实样本验证请求与回复解析，完成离线正确/错误夹具。证据不足时交付最小缺失信息，不遍历未知命令。
4. 需要真实设备操作时，先写出具体字节、接口、超时和副作用；未获当前会话相应授权才询问，已有授权不重复请求。
5. 接入严格匹配的读取后端；复用锁与取消契约。不能让加载普通标定 JSON 直接获得无人值守发送资格。
6. 检查 CLI、结果字段/状态、UI 标题/托盘、权限规则/安装器、测试夹具和引导文档，不能只改协议文件就宣布适配完成。
7. 把修改、已确认风险、已排除机制、未覆盖状态和复现命令分别报告；不要把旧设备或模拟测试当作新设备硬件证明。

交付：小步代码改动、真实证据与离线测试、兼容范围/不匹配原因、用户使用指引，以及未完成硬件场景清单。
