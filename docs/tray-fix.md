# 托盘问号与位置修复（2026-10-30）

## 问号

确认的问题：服务在读取失败时已经保留历史电量，但托盘对所有非 ok 状态都传入空值，导致过期读数仍被画成问号。

修复后，有历史值时继续显示该数字，改为灰色；悬停注明“上次 xx%（已过期）”、样本时间和失败原因。首次尚无数据或确认新接收器后尚无读数时仍显示问号，避免把另一台设备的旧电量当成当前值。不把休眠、未连接或未验证 0 伪装成新鲜值。

刷新只发送实际发生变化的图标/标题信号；检查时间更新只更新 tooltip，不重新注册图标。

## 左右顺序

本机为 GNOME Shell 46，Ubuntu AppIndicators 扩展的 `indicatorStatusIcon.js` 用 `Main.panel.addToStatusArea(..., 1, tray-pos)` 将应用图标插到相同位置。因此其他应用出现、退出或重新注册时，左右顺序可变化。单改本应用的 Id 属性不能保证固定顺序。

应用现在先申请并注册固定服务名 `org.keyboardpower.Tray`，避免宿主用每次变化的 `:1.N@/StatusNotifierItem` 作身份。实际宿主的 RegisteredStatusNotifierItems 已确认包含该固定名字。固定身份有助于识别，但不等于宿主排序策略已改变。

为固定本工具，另准备了 GNOME 用户扩展：

- 源码：`packaging/gnome-tray-position/`。
- UUID：`keyboard-power-position@local`。
- 只将本工具固定在其现有面板区域的最左侧，不改变其他图标之间的相对顺序、不修改系统 Ubuntu 扩展源码。
- 使用事件加一次性 idle 合并，无循环轮询。禁用会断开信号、移除待执行回调，并尽可能恢复原位置。
- 仅针对已核对的 GNOME 46。Python 工具不依赖该扩展，Node 只用于排序模型开发测试。

经安装授权，已运行 `tools/install_tray_position.py`，安装到用户扩展目录并将本 UUID 加入启用列表，保留原列表中的其他扩展。安装器拒绝覆盖已有不同文件。当前 GNOME 会话尚未识别新安装的本地扩展，需要保存工作后**注销并重新登录**；未自动注销或重启 GNOME，不能宣称实际固定顺序已验收。

生效后撤销：`gnome-extensions disable keyboard-power-position@local`。如果没有托盘宿主，或宿主/其他布局扩展同时移动同一个图标，仍需按实际桌面排查。
