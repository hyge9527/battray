# 新增设备：适配流程与自动化边界

适用于维护者。普通使用见 [使用引导](usage.md)。
当前只有本机 F98Pro 厂商协议完成实测；下面将现有操作与后续设计分别说明，避免把方案写成已实现功能。

## 自动化能做到哪里

可以自动收集能力、匹配**已经验证**的设备配置、运行离线协议测试；不能仅凭 VID/PID 或一个变化字节可靠推断未知电量协议。

| 环节 | 当前能力 | 适合后续自动化的部分 | 必须保留的人工证据/门槛 |
|---|---|---|---|
| 发现 | sysfs/HID 枚举、描述符、接口归组、权限状态 | 生成身份清单、描述符 hash 和差异 | 核对照片、型号、接收器归属 |
| 系统电量 | 与目标关联的 power_supply/UPower 来源选择 | 对已明确归属的来源自动刷新 | 来源真属于目标，未知/等级/时间有效性 |
| 标准 HID | 字段发现；显式 Feature 调试及候选解码 | 按描述符解析报告长度、编号与位字段 | 未加入后台，须验证实际设备数值；不监听普通键盘 Input |
| 已知厂商协议 | F98Pro 静态适配器、版本检查、严格回复校验 | 注册表按严格指纹选择；冲突拒绝 | 固件/版本兼容性、未知设备不进入发送 |
| 新私有协议 | 显式监听/Feature 转储/手动试发/离线标定 | 辅助对比样本、生成 parser 与测试草稿 | 命令含义和设备屏幕/官方值对照，禁止盲试指令 |
| 权限与安装 | 本机 F98Pro 专用规则/安装器 | 为已确认接口生成待审阅规则 | 管理员明确安装，不能自动放开所有 hidraw |
| 验收 | 单元测试与显式桌面验收脚本 | 隔离环境自动执行测试矩阵 | 充电、断连、重插、睡眠、低电量等真实设备状态 |

“自动匹配既有适配器”与“自动逆向未知设备”是不同能力。目前前者也只有 F98Pro 专用分支，不是一个可加载任意 JSON 的框架。

## 1. 建立证据包，暂不发送设备命令

记录型号/照片依据、连接模式、USB VID/PID、产品字符串、bcdDevice、物理路径、接口号、顶层集合、Report ID/长度、描述符原文及 SHA256。
型号与 USB 版本/固件版本分开；同 VID/PID 不等于同设备，蓝牙和 2.4G 也可能是完全不同协议。

```bash
python3 -B my_devices.py --list-devices --json
python3 -B my_devices.py --diagnose --vid VVVV --pid PPPP --json
```

`VVVV/PPPP` 是要替换的十六进制占位符，不要原样执行。必要时加枚举出的 `--usb-path` 消除同 ID 多接收器歧义。
节点在沙箱不可见与宿主无访问权限是不同问题。先查看宿主，再决定是否需要针对性 udev；不以 root 启动 UI，也不解绑键盘驱动。
分享诊断信息前人工检查型号、路径、序列号等是否需要脱敏。未经明确保存请求，不自动生成报告文件。

完成条件：唯一目标已确认，知道每个接口是什么、能否访问；不能把“接收器在线”写成“键盘在线”。

## 2. 系统来源优先，然后判断报告类型

先确认内核/UPower 是否提供与目标关联的真实百分比，避免重新实现已有能力。
若只有离散等级则显示等级/估算，不伪造成精确百分比；检查 present、更新时间和未知值。

描述符出现 Battery Strength 时，确认 Input/Feature、位偏移、逻辑范围和报告编号。当前调试界面的 Feature 按钮会对明确声明的报告附加标准字段候选解码；命令行 `--read-feature` 继续只输出原始字节。该能力只有合成夹具验证，未加入后台自动来源，仍须核对设备实际电量。
若没有字段，只能说明描述符没有声明标准字段，不能证明固件不提供私有电量。

## 3. 对未知厂商协议，先证明命令是读取

优先查目标型号/版本的官方通信或已有实测源码。其他型号的相似报文只作为候选。
不要依次遍历各厂商命令表，也不要用灯效、重置或固件命令测试通道是否可用。

当前实验入口：

```bash
python3 -B my_devices.py --debug-panel
python3 -B my_devices.py --listen /dev/hidrawN --duration 2
python3 -B my_devices.py --read-feature /dev/hidrawN --report-id 0xNN
```

`hidrawN` 与 `0xNN` 都须由当前枚举替换。监听/发送仅允许纯厂商集合；Feature 只请求描述符声明的 ID。
手动发送先核对完整缓冲区：未编号 Output 的 hidraw 缓冲区首字节为 `00`，读取未编号 Input 则没有此前缀。
F98Pro 是 32B 载荷/33B 写缓冲区，不能推广成所有设备都这样。
GUI 的发送按钮会显示字节并要求确认；CLI `--send-report` 本身就是显式执行动作，不应用于无人值守适配。

完成条件：能解释请求、副作用、报文长度、返回校验和超时语义；没有依据就停在“协议未知”。

## 4. 标定只产出候选，不直接装入后台

在 JSON 标定页填写报告编号、完整输入报告长度、位偏移、位宽、端序、倍率/偏移、原始值范围、回复前缀与校验方式。
偏移从完整 hidraw 输入缓冲区起算：编号报告含 ID 字节，未编号报告不含虚构的 `00`。
版本 1 中 `reply_prefix_hex` 和 `request_buffer_hex` 可省略，按空字符串处理；提供时必须为字符串。SHA256 必须是 64 位小写十六进制字符串。
这些字段描述解析条件，**并不授权自动执行 request_buffer_hex**。

用真实完整报告离线换算：

```bash
python3 -B my_devices.py --decode-report '完整十六进制报告' --profile /path/to/profile.json
```

不能只用自己构造、自己解析的样本证明兼容。至少记录不同电量、充电/非充电、休眠/断开时的观察，并与屏幕或官方值对照。
未覆盖状态必须明确标为未验证；0 可能是占位值，不能默认代表空电量。

## 5. 将候选接入代码，保持边界可审查

项目使用静态注册表和适配器契约。新增已知协议设备按以下顺序接入：

1. 在 `adapters/profiles.py` 中增加精确身份档案，复用 `domain.matching.match_profile`；未验证版本不给发送资格。
2. 新建独立适配器模块，声明 profile、实现 match/read。请求构造和回复解析保持纯函数，读写使用原有事务/取消边界；新协议不要复用无关握手。
3. 提供真实请求/回复夹具、身份负例、超时与取消断言。通过独立实机对照后才加入 `application.registry.REVIEWED_ADAPTERS`，不动态导入任意路径或 JSON 插件。
4. 来源优先级和缓存回退由 `application.reader` 管理，返回 `BackendResult`，旧 CLI 字段由 `to_legacy()` 统一生成。适配器不能导入 Tk、写用户设置或自行重新枚举。
5. 面板现已按显式绑定生成卡片；安装权限仍要求独立审阅的 `AccessPolicy`。新增设备应补充最窄规则及其测试，不能只加入读取注册表就扩大 udev 授权。`--onboard` 可只读显示匹配和权限计划。

已实现的适配器契约：

```text
profile -> DeviceProfile
match(interfaces) -> MatchResult
read(interfaces, ReadContext(cancel_fd, trace, clock)) -> BackendResult
BackendResult.to_legacy() -> 现有 CLI / IPC 字典
```

统一结果继续保留 `device/percent/source/updated_at/checked_at/status/reason`。
`percent=None` 表示未知，不能把失败换成 0；`updated_at` 是数据时间，`checked_at` 是本次检查时间，二者不互换。
新增状态前同时检查 CLI 退出码、Panel 的 stale 合并、Tray 的 `?` 图标、IPC 和用户文档。

涉及文件不仅是 `aula.py`：还包括 `diagnostics.py`、UI/托盘名称、调试模板/默认选择、CLI 默认参数、权限规则/安装器、验证工具的固定 F98Pro 断言及文档。
匹配资格与过期读数由统一模型管理；新增后端必须验证相应负例和结果序列。

## 6. 验收后才允许自动轮询

| 检查 | 通过标准 |
|---|---|
| 身份负例 | 同 ID 的不同产品/版本/描述符、重复候选均不能误发 |
| 字节夹具 | 真实已知请求与回复，错误长度/编号/校验/范围被拒绝 |
| 并发与退出 | 取消前不发送、读取中退出、调试与常驻互斥、无残留 fd/线程/子进程 |
| 来源与时间 | 不拿主机电池代替外设，不混淆缓存时间、采样时间和查询时间 |
| 用户状态 | 休眠、关闭、未连接、低电量、充电、重插有真实观察或明确未覆盖 |
| 桌面与性能 | 面板/托盘/单实例/75 秒 CPU，测试前说明会关闭实例并发送查询 |
| 权限与升级 | 非 root 运行、权限只作用目标接口、旧 JSON/CLI/自启不被默默迁移 |

设备清单应区分：已发现、协议候选、单次实测、指定版本支持、完整场景验收。当前 F98Pro 是“本机指定版本单次对照及部分运行场景实测”，不是所有 F98Pro 固件的认证。

可选使用 [AI 适配提示词](prompts/adapt-device.md)。
